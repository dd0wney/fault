# Handoff: 2026-08-29

## Goal

Build a strict Go testing library from the fault-injection work in `../graphdb`.
Became **github.com/dd0wney/fault** — SQLite's I/O-error sweep as a Go library,
with an eventual Go standard library proposal as the long-term aim.

## Completed

- [x] `fault` — the core. `Sweep`, `Points`, `Points.Trip`. Three exported
      names, zero dependencies, `go 1.23.0`. Frozen surface.
- [x] `fault/fs` — filesystem adapter. Wraps rather than replaces. `Op` strings
      measured against the real `os` package, not remembered.
- [x] `fault/alloc` — both SQLite out-of-memory loops, plus `Outstanding()`.
- [x] `fault/role` — per-actor sweeps with the stability check.
- [x] `fault/tools` — `go tool coupling`: DO-178C 6.4.4.d coupling coverage.
      `resolve`, `measure`, `checkComplete`, all working.
- [x] CI: 3 OS × 2 Go versions, format, zero-dependency gate, mutation gate,
      govulncheck, coupling gate. Every gate has a selftest that runs **first**.
- [x] README, package docs, and two design specs in `docs/design/`.

31 commits, 105 tests, CI green on `4ca3b62`, local and remote in sync.

## In Progress

Nothing. The tree is clean and everything is pushed.

## Open Questions

- **`fault/role` divergence message with long trace elements.** Recorded as an
  open question in `docs/design/2026-08-29-fault-core.md` §11.1 rather than
  designed, because no adapter yet produces them. Do not design for it without
  evidence.
- **Standard library proposal.** Odds are poor and the doc says so. The route is
  import count over years (`slices` had 1,541 importers at proposal time), not
  argument.

## Known Gaps, Recorded Not Hidden

- The mutation gate **stops at the module boundary** and does not cover `tools`,
  which scores 0.39. `go list ./...` from root cannot see a separate module.
- No crash simulation and no short-write injection. Both are documented
  limitations in the package doc, with the worked example of what a clean sweep
  therefore does *not* prove.

## Next Steps

1. Raise `tools` mutation coverage, or add a second gate with its own baseline.
2. Short-write injection in `fault/fs` — cheap, and catches a real bug class.
3. Crash simulation — SQLite's third loop. A design of its own.
