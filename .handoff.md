## The two decisions, both settled

**`ResetSession` still consumes no operation index, and the reason changed.**
The reason on record was pool timing, which is true and is the smaller half.
`sql.go:1353` discards any error from `resetSession` that is not
[driver.ErrBadConn] and hands the connection over anyway, and `ErrInjected` is
deliberately not one. So counting it would consume an operation index, inject
an error nobody ever sees, and let the pass report a pass — the shape
`Fault.Err` refuses for a short result set, manufactured on every sweep of
every scenario. `sql/doc.go` and the test both carry that now.

## The rule 3 hole, and what closed it

The core's contract names rule 3 as the one that breaks silently and says the
only countermeasure is "a test that counts operations independently and
compares".

**Measured on 2026-08-31.** A seventh method added to `fs.FS`, implemented on
`Fault` without calling `Trip`, passed EVERY gate here:

| Gate | Result with the violation in place |
|---|---|
| 242 tests, six packages | all `ok` |
| `go vet` | exit 0 |
| coupling gate | 98.4%, exit 0 |
| mutation gate on `./fs/` | **1.000000, meeting its 1.00 floor** |

The mutation gate cannot express it: `return f.base.Chmod(name, mode)` has no
mutant meaning "this should have called Trip". The compiler forces every
implementation to be WRITTEN — it broke `remapFS`, `Recorder` and five test
stubs — and nothing forces any of them to COUNT.

The counting existed. The comparison did not: every table was hand-written.

`*/contract_test.go` in `fs`, `alloc`, `sql` and `crash` now reflect over the
interfaces and partition every method into counted (read from the SAME table
the behavioural test drives) and exempt (with the reason as the map value). The
identical probe now fails, naming the method.

Two things stay open and are stated rather than hidden. `Seek` and `WriteAt`
are optional, are not members of `fs.File`, and reflection cannot see them, so
their tables stay hand-maintained. And **rule 4 has no automatic check**,
exactly as the contract says.

## Context to remember

**Twenty-five gaps the mutation gate found in `fault/sql` across three tasks,
and a reader found none of them.** The scores went 0.750000, 0.738095,
0.873016, each time to 1.000000 after repair. Two were worse than a missing
assertion.

**The invented-failure class.** `if r.armed && r.n == r.at` becoming
`if true && r.n == r.at` changed no test result, and that version fails the
first row of EVERY result set, armed or not. Every test in the suite armed
something, so none could see it. A missed injection under-reports and its
report stays true. An invented one reports a defect the code under test does
not have, and every later finding then needs a person to re-derive whether it
is real. `fs`, `alloc` and `role` now each carry a zero-`Points` guard against
it, written by hand because the gate cannot express the mutant where the
condition has one operand.

**A control that did not run looks exactly like a property that holds.** A
`sed` that matched nothing left `alloc` unmutated, the test passed, and that
reads identically to a real pass. Every control now prints a count proving the
mutation landed before the test runs.

**Grep for the change, not for the file you expect to hold it.**
`mmap_snapshot_writer.go` is byte-identical between graphdb's two builds, and
the durability fix is one directory away in `mmap_snapshot_persist.go`. A
conclusion was reported as definitive on the strength of that one file and had
to be retracted.

**Two publishes alone did not discriminate.** With the scoped rule disabled and
everything else identical, the broken build passed. Attribution by changing one
thing, not by changing several and crediting the likely one.

**CI found three things no local check could.** `golangci-lint` cannot run on
this machine — binary v2.12.2 built with go1.26.3 against a local go1.27.0
standard library — so CI is the only judge of it. It found SA1019 on
required-but-deprecated interface methods twice, and `errcheck` on one-value
type assertions twice. `.golangci.yml` sets `check-type-assertions`, so the
two-value form is required, and it is better anyway: it turns a panic into a
sentence.

**An empty result was the instrument four times today.** `gh run view --log`
refuses while a run is in progress. `gh api` withholds a log containing
terminal escape sequences unless `--allow-escape-sequences` is passed. A
`grep -c` finding nothing exits 1, which reads as a failed command. A `|| echo`
after a pipeline never fires, because the pipeline's status is the last stage's.
Each returned nothing and read exactly like a real absence.

**`go list -m` outside a module prints `command-line-arguments` and exits 0.**
It answers, and the answer is not a module path. `go env GOMOD` prints
`/dev/null` there, so it is the probe that can say no.

**A recorded number that ages is not a broken gate.** `./sql/` measured
1.000000 at 24 mutants, then 42, then 63. The score never moved, which is
exactly why each re-read was necessary: an identical figure about a larger
artifact is a different claim, and nothing in the gate can tell them apart.

**Test DATA makes an assertion vacuous as easily as test logic does, and it
happened three times on `fault/sql` alone.** A driver whose context methods
disagreed with its plain ones. A driver implementing every optional interface,
so no fallback branch was reachable. And `testRows.ColumnTypeLength` returning
`(0, false)` — exactly what the wrapper returns when it does NOT forward, so
the two were indistinguishable and discarding the forwarded call changed no
test result. It returns `(42, true)` now, chosen because the fallback cannot
produce it.

**A no-count claim is only testable where something is armed.** A test that
asked a hundred schema questions under a zero `Points` could not detect a
count being added, because `Trip` never fires there. The assertion has to be
positional: arm operation N and require the operation that should be N to fail.

**A string replacement without an assert silently does nothing**, and it reads
as a passing test. Two instances today beyond the `sed` one already recorded:
a multi-line function body that no longer matched, and a script whose `assert`
threw after the first replace so neither edit was written at all.

**KILLING A MUTATION RUN LEAVES THE SOURCE MUTATED, and the gate caught it.**
go-mutesting edits in place. A `mutation.sh` run killed at a timeout left
`M crash/run.go` and a stray `.tmp` in a scratch worktree, and the next run
there refused rather than reporting:

	mutation: the test suite already fails, so every mutant would count as
	mutation: killed and the score would read 1.000 — refusing to report it

That refusal is the whole point of the guard. A failing baseline suite makes
every mutant count as killed and the score read 1.000, which is the most
dangerous false green available. Use a fresh worktree per run, and never reuse
one after an interrupted run.

**A test that asserts a no-count property is only testable where something is
armed.** A hundred schema questions under a zero `Points` cannot detect a count
being added, because `Trip` never fires there. Arm operation N and require the
operation that should be N to fail.

**Do not check out commits in a shared working tree.** graphdb may be owned by
a peer session. Use an isolated clone, and `--no-hardlinks` when the
destination is on another filesystem.
