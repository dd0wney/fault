## The result that matters

The sweep was pointed at graphdb and **hit their blind calibration target on the
first run**, without being told what the defect was, which operation was
missing, or where. It is their finding F9: `pkg/storage/vfs_helpers.go:20`,
`writeFileWithFS`, which opens, writes, closes and renames with NO `Sync` on
either the file or the directory.

It also found their SEVERITY was wrong. They had recorded a revert that WAL
replay would mostly recover. The sweep measured 9 of 38 states where
`snapshot.json` exists and is EMPTY and the store does not open at all. Their
words: "the empty-file state is a thing you only see by generating it."

The harness is a THROWAWAY scratch module importing both repositories through
`replace`, committed to neither. That dissolves the dependency question by
making it nobody's, and it is the pattern to reuse for cross-repository sweeps.
The bridge is fifteen lines, and only `OpenFile` needs a body: the two `File`
interfaces have identical method sets so the VALUES are assignable, while the
METHODS returning them are not.

## Context to remember

- **Thirteen of the defects found today were in the PLAN, not the code.**
  Implementers and reviewers caught them by checking rather than transcribing.
  The worst was a check that flagged `safeStore` — correct code — as broken,
  which is the single worst failure a crash simulator can have. Two others
  silently UNDER-reported: global deduplication hid nine of ten broken states in
  one row, and recording `O_TRUNC` as a plain open made a whole defect class
  unreachable.
- **The final whole-branch review found a Critical defect that all fifteen task
  reviews missed**, because every diff was correct in isolation. Five methods
  recorded an entry before the base call and kept it on failure. `defer
  fsys.Remove(tmp)` after a rename then logged a phantom entry and flagged
  correct code. A per-task review structurally cannot see that.
- **A test is not automatically a gate.** graphdb's `extfs` defined its own
  `ErrUnsupported` and five assertions checked it and passed, while
  `errors.Is(err, errors.ErrUnsupported)` — the idiom every Go caller reaches
  for — returned false. Their diagnosis: "the test could not see the gap because
  it was written from inside the same wrong model." Assert against an EXTERNAL
  contract, not your own constant.
- **A limitation that was never true** is a distinct failure from a stale
  number, and worse: re-running a number catches drift, and nothing re-runs a
  sentence in a design document that says "we cannot do X". Both of ours fell to
  a one-minute probe. See `[[strict-lib-verification-lesson]]`.
- **Do not report CI from local gates.** Windows was red on the first run for
  four leaked file handles — a bug on every platform that POSIX merely
  tolerates. `GOOS=windows go vet` and a cross-compile both passed.
