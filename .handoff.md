   `driver.Driver` — a seam the standard library already ships. A throwaway

## Context to Remember

- **`fs.New` and `fs.NewShortWrite` return `*fs.Fault`, not `FS`.** Breaking,
  and larger than it looks: a function VALUE of `New` is no longer assignable to
  one returning `FS`, because Go has no covariance in a result type. This
  repository's own `shortwrite_test.go` did exactly that.
- **`docs/couplings.tsv` names symbols as TEXT and nothing compiles it.**
  Renaming an exported type left two rows pointing at a symbol no file declares.
  The gate refused rather than reporting a smaller number. Grep the registry on
  any rename.
- **`go-mutesting` mutates source files IN PLACE.** Never run the mutation gate
  concurrently with anything else in the same tree.
- **TEN instrument defects in one day, and the catch always came from outside
  the head that made the error.** Five were mine: an invented 92.6%, a wrong
  `ReadAt` claim, an unverified "Seek is expensive" claim, a "source-compatible
  in practice" claim that was not, and a shipped `doc.go` predicate that could
  not pass. The last was a `jq` wait loop that declared nine checks green while
  three were still running, because `//` substitutes only for `null` and the
  empty string is truthy.
- **A test is not automatically a gate.** A test written from inside the author's
  model inherits its blind spot. Assert against an EXTERNAL contract — the
  standard library's documented behaviour, a second reader, a control that must
  fail — not against your own constant.
- **Naming a failure mode does not inoculate you against it.** An implementer
  caught the flat-invariant defect in the plan in the morning; the same defect
  was rebuilt in the graphdb harness that afternoon.
- **Thirteen of the crash plan's defects were in the PLAN, not the code**, caught
  by implementers and reviewers who checked rather than transcribed.
