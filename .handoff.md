## Method notes worth carrying

**Re-measure the classification.** A survivor read is a claim about the code,
and the gate corrected every read made today: covdiff 7 where 6 were
predicted, coupling 82 where 22 were, crash 38 where 36 were. Compare the
lists by identity, not the counts: a count can agree while one gap survives
and one equivalent dies.

**A test that derives its fixture from the constant it pins cannot fail on
the constant.** The name-cap test computed its path length from `maxNameLen`,
and a cap of 79 or 81 moved the test with it. Use the measured literal and
say why.

**An absent check reads like a queued one.** A conflicting pull request gets
no `pull_request` run at all, and a watcher that waits for "no check
pending" waits forever. `gh run list --branch` returning nothing, against a
control of runs on other branches, is the diagnostic; `gh pr view --json
mergeable` names the cause once GitHub has computed it. The route without a
force-push is a fresh branch from `main` with the commits cherry-picked.

**A reader at the highest reasoning effort can produce nothing.** A sonnet
agent at effort xhigh spent its whole output budget thinking, twice, and
wrote no line. Smaller chunks, an explicit model pin, and an instruction to
append results to a file in groups of eight gave three complete reads.

**The wrapped error repeats the value.** `fmt.Errorf("%q: %w", v, err)` around
a `strconv` error puts the bad value in the message twice, so "the message
names the bad field" must anchor on the label with the value beside it.

**A later message masks an earlier refusal.** With `os.Open`'s refusal gone,
the nil handle reaches the next stage, whose message names the same path.
Assert "open " and the path, which only the refusal prints.

**Per-pass leak controls are wrong under a sweep.** The pass that arms the
first successful open holds nothing; ask "was anything ever opened" of the
scenario.

**Windows is the second reader.** The FS predicate table's first run there
found that a real error's class is a fact about the os package on that
platform, and the row now records both.

**The worktree guard, and the ten-minute background limit.** In
`.claude/worktrees/` the shell refuses compound commands whose text names
git — a path holding `github.com` counts — variables in command position,
and long chains. Put anything with a loop or a chain in a script file under
the scratchpad and run the file. A background Bash call is killed at ten
minutes, and a mutation run takes longer: start it detached (`setsid nohup`)
from a script that writes a done marker, and wait on the marker. The local
`golangci-lint` is built with go1.26.3 against a go1.27.0 toolchain and fails
on every package; run it as `GOTOOLCHAIN=go1.26.3 golangci-lint run`.

**An assertion that a random order satisfies half the time is a coin flip,
not a test.** `slices.IsSorted` on two elements passes by chance; assert the
literal, with enough elements that no rotation of the insertion order is
sorted.

**A worker can invent a quoted line.** The fix-up worker wrote a line into a
commit body as if it were captured gate output, caught it on re-reading, and
amended the commit before anything depended on it. Quote only what a file or
a terminal holds, and read the commit body back before the next commit.

**An absence check needs a positive control in the same test, and a length
check needs the content.** "Observed does not contain the bypass path"
passes on an empty list, and "eight subsets" passes on eight duplicates.
Assert the served path is present first, and assert the literal, worked by
hand.

**A runtime echo of a compile-time assertion can never run.** A dropped
method fails the build of the package that holds both, so the runtime test
never runs and its claim to name the adapter is false. Say the build is
the check.

**A `continue` that every test reaches with one element is a `break`.**
Give the guard a fixture with something after the guarded element.
