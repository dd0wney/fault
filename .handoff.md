## Method notes worth carrying

**Re-measure the classification.** A survivor read is a claim about the code,
and twice today the gate corrected it: covdiff left 7 where 6 were predicted,
and coupling left 82 where 22 were, because the read had marked fifty
discarded return values as "pinned by the refusal tests". A test that reads
`err` cannot see a value in a slot it never reads.

**The wrapped error repeats the value.** `fmt.Errorf("%q: %w", v, err)` around
a `strconv` error puts the bad value in the message twice, so "the message
names the bad field" must anchor on the label with the value beside it.

**A later message masks an earlier refusal.** With `os.Open`'s refusal gone,
the nil handle reaches the next stage, whose message names the same path.
Assert "open " and the path, which only the refusal prints.

**Per-pass leak controls are wrong under a sweep.** The pass that arms the
first successful open holds nothing; ask "was anything ever opened" of the
scenario.

**A reviewer applied a mutant in the session worktree and left scratch files
in the scratchpad.** Check `git status --untracked-files=all` before every
commit, and never commit with a mutant on disk.

**Windows is the second reader.** The FS predicate table's first run there
found that a real error's class is a fact about the os package on that
platform, and the row now records both.

**The worktree guard.** In `.claude/worktrees/` the shell refuses compound
commands that name git, variables in command position, and long chains. Use
plain single git commands, `go -C <dir>` for the tools module, and a script
file under the scratchpad for anything with a loop.
