## Issue A — `fault/sql` degrades the driver it wraps, one and two levels down

**This corrects a claim I made today.** PR #13's body and its commit message
say "fork 3 is closed: the `known` map is empty, so an entry in it is a
regression". That is true of what the test looks at, and the test looks at one
of three levels.

**Measured.** The reflective test names ten interfaces, and every one of them
is a `driver.Conn` interface: `ConnPrepareContext`, `ConnBeginTx`,
`QueryerContext`, `Queryer`, `ExecerContext`, `Execer`, `Pinger`,
`SessionResetter`, `Validator`, `NamedValueChecker`.

The wrapper's other two types implement only their required methods:

| Type | Implements | Optional interfaces it does not |
|---|---|---|
| `stmt` | `NumInput`, `Close`, `Exec`, `Query` | `StmtExecContext`, `StmtQueryContext` |
| `rows` | `Columns`, `Next`, `Close` | the five `RowsColumnType*`, `RowsColumnScanner`, `RowsNextResultSet` |

**The consequence, read from the standard library rather than inferred.**

`ctxutil.go:81` — if a `Stmt` does not implement `StmtQueryContext`,
`database/sql` calls `si.Query(dargs)` instead, and the context is gone. A
caller's `QueryContext` cancellation stops working the moment the driver is
wrapped. The same holds for `StmtExecContext`.

`sql.go:3307` and `sql.go:3312` — `Rows.ColumnTypes()` type-asserts the driver
rows for `RowsColumnTypeScanType` and `RowsColumnTypeDatabaseTypeName`. A
wrapper implementing neither returns less information than the unwrapped
driver, silently.

This is PR #2's lesson at two more levels: a method set tracked by hand drifts,
and the drift is invisible because everything still compiles.

### 1. The reflective test covers all three levels

Do this FIRST, and watch it fail. A test that is written after the fix proves
that the fix is present; a test written before it proves that the gap was real.

- [ ] Extend the reflective check to `driver.Stmt` and `driver.Rows`, driving
      each from a wrapped base that implements the optional interfaces.
- [ ] The test driver's `testStmt` and `testRows` must implement MORE than the
      wrapper does, or the check passes for free — the same rule fork 6 states
      for the connection.

**Acceptance**

- The test FAILS before task 2, naming each missing interface.
- The failure names the consequence, not only the absence: a dropped context
  for the statement level, a degraded `ColumnTypes` for the rows level.
- The positive control holds: if the test driver implemented none of them, the
  check must refuse rather than pass.

### 2. Forward the statement and rows interfaces

- [ ] `StmtExecContext` and `StmtQueryContext`. They REPLACE `Exec` and
      `Query` rather than adding a call, so each must consume exactly one
      operation index and not two.
- [ ] The `RowsColumnType*` set, `RowsColumnScanner` and `RowsNextResultSet`,
      forwarded when the base offers them.
- [ ] Decide, and write down, whether `RowsNextResultSet.NextResultSet` counts.
      It advances to another result set, so it is closer to `Next` than to
      `Columns`. The row rule says one index per result set; a second result
      set is arguably a second one.

**Acceptance**

- The test from task 1 passes, and the `known` map stays empty at all three
  levels.
- The operation count does not move for any existing test. That is the
  property fork 3 exists to protect, and it is the one most easily broken by
  this change.
- `./sql/` is re-measured and the figure re-recorded. It will not be 63 any
  more.
- A test shows a context cancellation reaching the base driver through the
  wrapper, because that is the behaviour the gap removed.

## The two decisions

Neither is a defect, and both were deliberately left rather than taken.

**`ResetSession` consumes no operation index.** The pool decides when to call
it, so counting it would make the N-th operation differ between two runs of one
scenario. Documented in `sql/doc.go` and held by a test. Reversing it is small.

**`./role/` has a floor of 0.74 and a measurement of 0.774194.** The house
method gives 0.77, and `./crash/` raised itself from 0.75 to 0.77 on exactly
that method. 0.74 leaves about two survivors of slack, and slack of that kind
is what hid the `./crash/` trend. 0.77 leaves less than one mutant of margin.
